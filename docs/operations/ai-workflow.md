# AI engineering workflow

**Status:** current · setup inspected 2026-10-21, workflow v2 adopted 2026-10-24

[AGENTS.md](../../AGENTS.md) owns shared rules, task sizes and skill routing. [CLAUDE.md](../../CLAUDE.md) imports it with `@AGENTS.md`; Cursor retains its existing project instructions and shell rule. [Verification](verification.md) owns check selection, commands and service isolation. This setup changes engineering infrastructure, not StackPulse application behavior.

## Work loop

1. Classify the [task size](../../AGENTS.md#task-size), then read what it requires via [agent start here](../AGENT_START_HERE.md): owning docs, code and callers. Inspect Git status and preserve unrelated work.
2. Define the outcome, assumptions, affected boundaries and proportionate verification. Use Grilling only for consequential unresolved decisions; approved implementation does not need another interview.
3. Make the smallest complete change with existing patterns. Preserve auth/ownership, ingestion recovery, data and AI-cost safeguards.
4. Run relevant checks and review the complete affected flow. Ponytail Review supplies engineering review; T2 and CI/guard changes add an independent `codex-review`, and auth, ownership, cron-auth or secret changes add `/security-review`. Report findings before review fixes. Full audits and launch gates remain conditional.
5. Update owning docs for durable changes; report fresh PASS / FAIL / NOT RUN evidence, skips, limitations, cleanup and next steps. Installation, discovery and actual activation are separate claims.

## Maintenance

Run from the repository root; Node alone is sufficient:

```bat
node scripts/sync-agent-skills.mjs
node scripts/sync-agent-skills.mjs --check
node --test tests/agent-skills-sync.test.mjs
```

With application tooling installed, `pnpm test:agent-workflow` runs the same regression tests. The dependency-free synchronizer validates all managed packages and hashes before any target writes. It rejects unsafe paths, duplicate names, links, missing source resources or license (`LICENSE` or `LICENSE.txt`) and unexpected files inside a managed target package. It repairs missing/stale target copies, normalizes CRLF for comparison, and preserves unrelated custom skills and Claude settings. `--check` is read-only; neither mode fetches upstream or removes files. ESLint and Prettier exclude only the two vendored skill trees so upstream examples/content are not treated as application code or reformatted; their integrity gate remains the hash check.

For a deliberate source update, retrieve the approved revision from the official source, review the complete package/adaptations/license, and update only truthful provenance and computed hashes. Edit canonical files, never generated copies; then synchronize, run integrity/regression checks, validate YAML/frontmatter and review the diff. Do not automatically upgrade skills. A hash match proves recorded content, not safety or model behavior.

## Local skills, guards and CI

Three skills are authored for this repository, adapted from Fintech Lab at `7f5e1c2` with its finance-specific wording generalized to StackPulse's T2 areas. They are not in the upstream manifest; `node scripts/check-engineering-workflow.mjs` checks that the Codex and Claude copies are identical and that the orchestration guards are present.

- `codex-review`: independent read-only Codex review of a committed branch or design, then triage. The prompt is read from stdin (`codex exec … - < .tmp/<task-slug>/review-prompt.md`), so it runs in Command Prompt and POSIX shells. Falls back to a fresh read-only subagent.
- `ship-pr`: rebase, guards, pre-PR checks, review prerequisites and a template-based description; pushes or opens a PR only after explicit approval.
- `engineering-workflow`: explicit-only orchestration with `scripts/engineering-workflow-state.mjs` as its checkpoint/resume ledger under ignored `.tmp/agent-workflows/`. Two changes from the reference helper: an unused variable is removed, and re-verification after a correction may re-record `verification.json` (reviewer reports stay immutable), covered by `tests/engineering-workflow-state.test.mjs`.

Guards: `scripts/check-pr-review-signals.mjs` labels `t2-area` and `guard-change` PRs from the path lists in the script, rejects focused, skipped and todo tests in the diff and anywhere in each changed test file (the `skip: !<condition> && '<reason>'` env gate and `// allow-skip: <reason>` pass), and lists removed tests, including those of deleted files, and assertion losses. A blocklist cannot be complete: disabling a gate variable itself (for example `const enabled = false`) is left to review. `scripts/check-migration-history.mjs` keeps `drizzle/` append-only. Their regression tests live in `tests/` and run with `pnpm test:agent-workflow`.

[CI](../../.github/workflows/ci.yml) jobs: _Agent workflow integrity (ubuntu-latest / windows-latest)_, _Migration history is append-only_ and _Review signals_ (pull requests only), and _Lint, typecheck and offline tests_. It uses `contents: read` (plus label writes for _Review signals_), disables checkout credential persistence, configures no secrets or database, and runs no build or deploy. Hosted execution is unverified until GitHub runs it.

Unlike Fintech Lab, StackPulse has no development Compose stack or generic integration runner. Existing Node SQL tests already enforce isolation, and the skill suites require a workspace-owned native cluster proof that container paths do not satisfy. This migration adds no Compose stack or runner and changes no test guards, application driver, dependency versions or deployment configuration. [Verification](verification.md#risk-based-verification) documents the real SQL/HTTP/hosted boundaries and the requirements for a future Docker runner.
